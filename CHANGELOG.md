## Unreleased - Fewer copies of an LLM key in deskd's and desk-agent's memory (`sub/lsub-iss20-key-zero`, ISS-20; deskd and desk-agent, nothing a member sees changes)
- **Fixed (security):** deskd's link to desk-agent wrote each frame from a heap buffer, so NIO copied it into a temporary direct buffer that it caches per carrier thread and never zeroes. A KEY frame's key, at the frame's end, stayed there past later, shorter writes. `AgentLink` now writes every frame through a direct buffer of its own and zeroes it after each piece (`writeThrough`).
- **Fixed (security):** deskd parsed a client's RPC request with jackson's shared buffer pool, which hands out the same `char[]` again without zeroing it, so an `agent.key.add` key stayed reachable until a longer string covered it. Requests now parse through `Json.parseRequest`, whose buffers aren't pooled and go with their parser: about 0.5 KiB more allocated per request. Every other parse keeps the pool.
- **Fixed (security, the Desk Engineer's review):** deskd's `rtc.sock` read buffer, which lives as long as the connection, kept the bytes of every envelope it had handled past the start a later, shorter read covers, an `agent.key.add` request among them. `RtcClient.drain` now zeroes what each read brought once its envelopes are handled, and the buffer is zeroed when the connection ends.
- **Changed:** desk-agent's `KeyLease.headerValue` makes one `String` of the prefix and the key, joined in an array it zeroes, rather than two.
- **Added:** desk-agent's `test-release-scripts.sh` fails if anything a desk runs names `jdk.httpclient.HttpClient.log`, `jdk.internal.httpclient.debug` or `javax.net.debug`, which would log a provider key's header or TLS plaintext.
- **Tests:** `AgentKeyTest` 2 new, `JsonTest` 2 new, `KeyRingTest` 1 new, `RtcClientReadTest` 2 new (both fail without the `rtc.sock` fix), and the release script's 3 "http logging" checks. The finding, path by path, with the uids, the risk and the options not taken: `docs/sub-status/iss20-key-zeroing-finding.md`. Security cleared it at `974b2db2` with no code findings (ISS20-P1 Low and ISS20-I1 Info, both outside this branch's code). Ships with the next deskd and desk-agent releases; release 3 is unaffected. Status: `docs/sub-status/lsub-iss20-key-zero.md`.

### Fixed
- `desk-data`, from `ma-desk-0.2.9` (`docs/sub-status/data-review-fixes.md`): a file rewritten in place while "Download your data" or a move read it could arrive as old bytes and new, and pass every check, as the end-of-file hash is of what was sent. The helper now checks the file didn't change (size, times, inode) from its first byte to its last, and if it did the read ends without a hash and is asked for again. A file that shrank or grew while it was read ends the same way.
- `desk-data`, from `ma-desk-0.2.9`: several big databases read at once could fill your desk's disk past the 2 GB it keeps free for the Browser, as each read checked the free space alone. Copies in progress now count against each other.
- `desk-data`, from `ma-desk-0.2.9`: a download or a move whose reader paused for 30 s had its read cut off and had to ask again, a database from the beginning. The helper now waits as long as `deskd` does, 5 minutes, as `deskd`'s API says.
- `ma-move`: a move could say done with your Browser copied while it was running. A pause of the cloud desk's Browser that it refused was skipped, one that ended with a dropped connection wasn't noticed, and it wasn't renewed past 30 minutes. Now it's asked for again, renewed, and if it's lost the Browser is listed again and its changes copied under a new one; a pause it can't get stops the move with nothing changed.
- `ma-move`: a file whose name isn't UTF-8 (a byte like `0xe9` from an old system) was left out of a move that said done, a database included. Names now go across byte for byte, and a name it can't carry stops the move instead of being left out.
- Agent app backend (`desk-agent`, `deskd`), from a review, in no release yet (`docs/sub-status/agent-review-fixes.md`):
  - An LLM key picked under the wrong provider, such as an Anthropic key (`sk-ant-…`) as OpenAI's, is refused on the desk with `bad_request`, `reason: key_malformed`, `detail: provider_mismatch`. It used to go to the other provider's API to be checked.
  - A `desk-agent` that stops reading no longer holds up a session: the Browser's calls stay quick, at most 16 of a session's calls wait on the Agent at once, a stalled request fails after 5 s and the link reconnects, and a desk stopping never waits on it.
  - Cancelling an Agent call, its deadline or a session ending no longer cuts the Agent's connection for every other session.
  - A long Agent conversation no longer loses its live updates: its snapshot is the newest messages that fit, with `older: true` when there are more, and `agent.thread.get` pages back with `before` (`services/deskd/docs/API.md` §11). It used to answer `too_large` past 1 MiB.
  - A model the Platform's price table lists at $0 in and $0 out counts at its provider's highest listed price, so a dollar limit still binds it, and `deskd` keeps only a price table `desk-agent` can use.
- Desk app: the fine borders the design always had now draw, in Light, Dusk and Dark: round the top bar's buttons, the desk switch and zoom, the bandwidth circle and its panel, menus and their dividers, the Picture quality menu, notices, the Browser window's header and bar, the welcome card and its tiles, and the export page's lists. They were missing, so edges were softer than intended, most of all in Dusk.
- `ma-move`: a move could say it was done with the Agent's recent threads and ledger left behind. A write to a SQLite database in WAL mode doesn't change the main file's size or time, so the last pass skipped every database outside the Browser. The last pass now reads every database in every part again, and one it can't read stops the move before anything on this desk changes. What's written on the cloud desk after a file's last read stays there, as `ma-move`'s README now says.
- `deskd`: reading files from a desk over and over no longer gets past the bandwidth limit. Only an export or a move is free, up to 3 times the desk's data volume in 30 days, which covers a full export, a move and retries. Past that, or on an ordinary session, the bytes count like any others. While a member is paused at a limit, those reads wait for the pause to end, with `reason: bandwidth_limit` and `resumesAt`, and an export within the free amount always goes through, so a paused member can still take their data away. See `services/deskd/docs/API.md` §12.
- `desk-rtc`: a `stats` asked for just as a session closed could leave out what that session had sent, so the desk's reported total briefly fell. A closing session now moves into the totals in one step.
- `deskd`: with no `desk-agent` on the desk, a refused Agent write (`agent.create`, `agent.key.add` and the rest) now says plainly that the Agent isn't available and nothing changed (`unavailable` with no `mayHaveApplied`), instead of that it may have applied, and the same request goes through once the Agent is there.
