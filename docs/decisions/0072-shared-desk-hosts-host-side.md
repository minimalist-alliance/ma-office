## Context
The owner, on what a member is promised: "We are NOT promising someone their own EC2 and never will". After shared-host test 3: "4 per c7g.xlarge will have to do" (ADR 0071, Accepted). Platform keeps the packing as a setting, `hosting#current` = `{instanceType: "c7g.xlarge", desksPerHost: 4}` (`ma-platform` ADR 0101, `sub/host-packing`). **Note, 2026-11-09:** ADR 0101's addendum moved the seed to `{instanceType: "m7g.xlarge", desksPerHost: 6}` (`scripts/hosting-set.sh --seed`; `image/host/recipe/files/etc/desk-host/desk-host.conf` defaults `DESKS_PER_HOST=6`). Figures below that say 4 per `c7g.xlarge` are the earlier packing and are kept as written.

Test 2 (`spikes/shared-hosts-test2/`) built a wall between desks on one machine and measured it. Test 3 measured it again on image 0.2.7, with every desk viewed. Both ran test plumbing:
- fixed fake credentials from a metadata stand-in on the host;
- `/data` as a directory on the machine's one disk;
- no CDP rule inside a desk, and no outbound shaper;
- `deskd` and `desk-agent` as plain processes, not in Docker.

The update policy (`draft-desk-app-contract.md` 13.9) says shared machines aren't designed. This ADR designs the host side, and Platform writes its own side below. Sections marked **(agreed)** were settled with the Platform Engineer on 2026-11-07 and are written as decided; the rest is the System Engineer's design. **Proven** means test 2 or 3 ran it, and **new** means nobody has.

## Decision

### 1. Packing (agreed)
Platform launches each shared host with the tags `DesksPerHost` and `HostingVersion`, and with `InstanceMetadataTags=enabled`. The host reads both through IMDS once, at its first boot, and keeps them on its root: a later boot that reads another number keeps the first and reports the difference. A change to `hosting#current` reaches new hosts only.

Each desk's share is test 2's formula, proven by both tests (a `standard` desk's; a slot's size class multiplies it, section 16):
- the same CPU weight as every other desk, with no CPU cap;
- a memory cap of (`MemTotal` − 640 MiB) ÷ `DesksPerHost`, which is 1,872 MB a desk at 4 on a `c7g.xlarge`;
- at most 8,192 tasks;
- inside that, each unit's own weight and cap, so `desk-stream` and `desk-rtc` (400) outweigh Chromium (100).

### 2. What runs where
| Part | Where | Status |
|---|---|---|
| Xorg (as `desk-x`), PulseAudio (as `desk-snd`), kiosk Chromium with its own sandbox on, `desk-stream`, `desk-rtc` | Each desk's container | Proven (tests 2 and 3; the wall test with the review's fixes) |
| `deskd`, `desk-agent`, `desk-notebook`, `desk-rtc`, `desk-stream` | Each desk, each in a runc sandbox of its own (below) | Proven in run 2: all five in their own sandboxes, a 60 fps stream with sound, `deskd`'s hello and its calls to the Agent and Notebook |
| `desk-agent-filter` and its resolver | Each desk's container | Proven (run 1: providers reached, others refused) |
| `desk-units`, `desk-data`, `desk-browser-policy`, `ma-selfhost`, `unattended-upgrades` | Each desk's container | New |
| `desk-init`, each container's first process | Each desk's container, from the host, read-only (section 3) | The wall test's `desk-init.py`; new as production code |
| `desk-host`: tags, slots and their records, the template, volumes, namespaces, firewall, counters, shaper budgets, the link to Platform | The host, as root | New |
| IMDS, the host role's credentials, SSM, the kernel, runc, nftables, the journal | The host | |
| Docker | Nowhere | New |

**`desk-init`, not systemd.** systemd can't be a container's first process inside the wall without `mount`, which the wall refuses on purpose (Docker's seccomp profile and AppArmor). So `desk-init` reads the image's own unit files: users, commands, restart rules, weights and caps, the `ExecStartPre=+` helpers as the desk's root, and the two socket-activated root helpers on `units.sock` and `data.sock`. `desk-browser-close` and `desk-units` go through it instead of `systemctl`. Of each unit's sandbox:
- it applies everything that needs no mount: seccomp, capabilities, no new privileges, address families, memory and tasks;
- **every process it starts gets the unit filter** (`WALL-01`): `clone` or `unshare` with any `CLONE_NEW*` flag, `setns` and non-native calls refused, `clone3` ENOSYS. The `ExecStartPre=+` and `ExecStartPost` helpers and the socket helpers get it too. Only `desk-browser`'s ExecStart goes without it, because Chromium's sandbox makes user, PID and network namespaces. A filter is inherited and survives `execve`, so nothing started from a unit can shed it, Chromium's binary exec'd by another unit included;
- `ProtectSystem`, `InaccessiblePaths`, `ReadOnlyPaths`, `PrivateTmp`, `PrivateNetwork`, `PrivateDevices`, `ProtectProc` and the rest that need a mount come from the services' own sandboxes below, not from file ownership.

**Docker: neither inside nor beside.** Inside, `dockerd` needs `mount` and overlay filesystems, which would undo the wall. Beside, one `dockerd` on the host can't put a container into a desk's own user namespace: `--userns-remap` is one range for the whole daemon. `ma-update` unpacks a release's image (its JVM or Node and its app) instead of running `docker load`, and each `run` gains a shared-host form (the Desk Engineer's). `desk-agent`'s class archive is tied to its path, which a release root keeps (`/app`, run 2), so it needn't be trained again.

**The services keep their sandboxes (`WALL-06`), by runc, not Docker (built and proven in run 2).** `desk-host` runs `deskd`, `desk-agent`, `desk-notebook`, `desk-rtc` and `desk-stream` each as a runc container of its own, made with `runc create` beside the desk's container at every start, before anything in either runs:
- **Namespaces:** each joins the desk's user namespace; `deskd`, `desk-agent` and `desk-rtc` its network namespace; `desk-stream` its IPC namespace (it reads the screen over MIT-SHM from the desk's Xorg) and an empty network namespace; `desk-notebook` an empty network namespace (`--network none`). Each has its own mount, PID, IPC (but `desk-stream`), UTS and cgroup namespaces.
- **Every runc input is the host's (`RC-01`).** Roots: `deskd`, `desk-agent` and `desk-notebook` get a read-only release root, a copy per slot of the release image `desk-host` unpacked itself from the image ID its own tree names (a host store, `/srv/desk-host/releases`), never the desk's `/opt/ma/<svc>/current`; `desk-rtc` and `desk-stream`, native programs on the image's libraries, get the read-only template. Namespaces: the desk's are joined through binds of its namespace files that `desk-host` makes in a host-owned per-slot directory at `runc create` (a private mount, since a mount namespace's file can't be bound where it would propagate into itself), never `/proc/<pid>/ns` at a later start. `/run` directories the desk shares with them (`/run/desk`, `/run/desk-agent`, `/run/desk-notebook`, `/run/desk-media`, `/run/desk-audio`, `/run/desk-ctl`, `/tmp/.X11-unix`): binds from a host tmpfs per slot, made fresh at each start. `/data` and each service's directory on it: `open_tree()` clones from the host's own mount of the volume, resolved with `openat2(RESOLVE_IN_ROOT | NO_SYMLINKS | NO_MAGICLINKS | NO_XDEV)`, moved in after `runc create` (section 5). A directory the desk's root turned into a link gets that service refused, never followed; the desk's own `desk-init` then replaces the link with an empty directory.
- **Each has its `run` flags:** its uid, no capabilities (`desk-rtc`: `CAP_NET_BIND_SERVICE`, as its unit), no new privileges, the slot's AppArmor profile, Docker's seccomp profile with no namespaces, no `setns` and `clone3` ENOSYS (the unit filter) and section 3's socket allow-list, a read-only root, private `/tmp` and `/run`, `/home` and `/root` hidden, memory with swap 0, tasks and CPU weight in its own cgroup `desk-<k>/svc-<name>` under the desk's share, beside the desk's own `desk-<k>/desk`, which alone is delegated to the desk's root.
- **Process 1 is `desk-svc`,** a small supervisor from the host's read-only `/sh2`, which restarts its service as the unit says, so a sandbox lives as long as its desk and nothing is mounted into it again. `desk-stream` stays on demand: `deskd` asks `desk-init` over `units.sock` as before, and `desk-init` (the desk's root, checked by peer uid) asks the sandbox's `desk-svc` over `/run/desk-ctl/desk-stream.sock`. No socket from a desk reaches the host.
- **A stop is signals only:** `runc kill TERM` to `deskd`'s sandbox, then the desk's (section 7), then the other four.

- `desk-data` runs as a non-root uid with ambient `CAP_DAC_READ_SEARCH` only, and `/data` read-only to it.
- PulseAudio (proven in run 2): module loading off, no `auth-anonymous` and no cookie: `/run/desk-audio` is `desk-snd:desk-audio 0750` and the native protocol takes only group `desk-audio` (kiosk, stream). uids 1100, 1103 and 1105 get EACCES on the socket, and the desk's root, which can open it, gets PulseAudio's own "Access denied".
- Xorg (proven in run 2, and on desks of their own as `DA-1`): `-auth` with a cookie made at every start that only Xorg's own user holds (`0600`), used once to add `SI:localuser` for kiosk, rtc and stream, which X checks by the socket's peer uid; and `-nolisten local`, so no abstract socket. uids 1100, 1103, 1105 and the desk's root are refused on the socket file, and nobody finds an abstract one. The cookie isn't handed to rtc or stream: their uid is their credential.
- The Agent filter's resolver runs inside the desk with no socket uid 1103 can use (the wall test ran a stub relay in place of `systemd-resolved`; F-CT and F-CTHOLE rerun inside a desk before the gate).
- The wall test's first form stays in `desk-init` as a fallback with `SH2_SANDBOXES` unset, not the gate: plain processes under the unit filter, `desk-notebook`'s uid refused every packet by the host's rule in the desk's firewall (UDP got EPERM, TCP is dropped). It isn't the gate.

### 3. The wall
Test 2's wall stays as it was measured (proven; test 2's README, "The wall between desks"):
- its own user ID range per desk, and its own PID, mount, IPC, UTS, cgroup and network namespaces;
- its own copy of the root, its own display and sound, and its own address, with the host dropping desk to desk, desk to IMDS and spoofed sources;
- Docker's capabilities minus three, `no_new_privs`, Docker's seccomp profile with namespace creation allowed for Chromium's sandbox, Docker's AppArmor profile plus `userns,`, and Docker's masked `/proc` files plus seven;
- Chromium's own sandbox on.

New, each for the review; "proven" means the wall test ran it on one host with two desks (`spikes/shared-host-wall/`), and section 15 has each finding's proof:
- **Each desk's own firewall, inside its namespace.** `desk-host` loads the template's `nftables.conf` (never the slot's own copy, which the desk's root can edit) into each desk's network namespace after `runc create` and before `runc start`: the metadata address only for root and `deskd`, port 9222 only for root and `deskd` (the rule test 2 left out), the Agent's redirect and ADR 0036's `classify` chain. After its `flush ruleset` go the host's own rules: uid 1105 refused every packet, and a connection limit (below). The desk's root has no `CAP_NET_ADMIN` and no netfilter socket, so it can't change them. In a namespace owned by the desk's user namespace, `meta skuid` matches the desk's own uids, so the image's rules need no change: proven, with 9222 answering uid 1100 and refusing 1102 and 1103, and the filter carrying uid 1103 to the providers.
- **`ALL-09`, closed for netfilter (`WALL-01`).** Three layers:
  - every process but Chromium's tree has the unit filter (section 2), so it can't make a namespace at all;
  - the desk's AppArmor profile denies `net_admin`, `net_raw`, `sys_module`, `sys_rawio`, `bpf`, `perfmon`, `syslog`, `sys_ptrace`, `mac_admin` and `mac_override` to every desk process, audited. AppArmor checks whatever user namespace a process is in, so Chromium's browser process, where a sandbox escape lands, has none of them in a namespace it makes. Proven: uid 0 with every capability in its own user and network namespace still gets EPERM from `ip link`, `tc`, `ip xfrm` and `nft`, and the host's kernel logs the denials. `sys_admin` and `sys_chroot` stay for Chromium's sandbox, and `chrome://sandbox` still reads "adequately sandboxed";
  - `socket()` takes `AF_UNIX`, TCP, UDP and ICMP over IPv4 and IPv6, and `AF_NETLINK` with `NETLINK_ROUTE` only, native arm64 calls only (Docker's profile let 32-bit ARM calls and every family but `AF_VSOCK` through). **`RC-02`:** each type is pinned (`SOCK_STREAM` with protocol 0 or TCP, `SOCK_DGRAM` with 0, UDP or ICMP, `SOCK_NONBLOCK` and `SOCK_CLOEXEC` masked), so protocol 0 can't pick SCTP or DCCP, and `socketpair()` takes `AF_UNIX` only (Docker's profile allowed it for every family, which autoloads a family's module and gives TIPC a working pair). The host blacklists 64 protocol modules no desk needs (`install <module> /bin/false`; `kernel.modules_disabled` would also stop the host loading what it needs later), and unloads the vsock ones the AMI loads at boot.
  Proven, the blacklist included (run 2). The kernel stays the wall for everything else.
- **Chromium's uid is Chromium's only (`WALL-01`).** Xorg runs as `desk-x` (1107) and PulseAudio as `desk-snd` (1108); `kernel.yama.ptrace_scope` is 2, which `verify.sh` checks; `NativeMessagingUserLevelHosts` is off in the managed policy.
- **One AppArmor profile per slot (`WALL-10`, run in the test),** whose signal, ptrace and unix peer rules name only that slot. Every slot's uid range, for the 29 slots a host could have, is reserved for a `nologin` system account `desk-slot-<k>` in `/etc/subuid` and `/etc/subgid`, and the host check fails on any other entry overlapping one or any host process in a range (proven in run 2). The image's own desk users came with ranges there, `desk` 165,536 (slot 1's) to `agent-filter` 558,752 (slot 7's), since `useradd` made them: the host removes them, as no host process runs as a desk user.
- **Neighbour limits (`WALL-07`, `IN-06`, `ALL-10`).** Each desk's cgroup has, beside section 1's share:
  - **The memory rule, proposed to the Security Analyst in place of run 1's `memory.swap.max` 0 (run 3, 2026-11-08):** `memory.swap.max` 2 GiB, `memory.zswap.max` 1,000 MiB and `memory.zswap.writeback` 0 on each desk. The host image runs Debian's generic arm64 kernel (`linux-image-arm64`, 6.12; the cloud kernel builds no zswap), with zswap on at boot (`lz4`, `zsmalloc`, at most 50% of RAM, its shrinker off) in front of an 8 GB swap file and host zram off. A desk's compressed pages are charged to its own cgroup, inside its `memory.max`; `memory.zswap.max` bounds them; with writeback 0 none ever reaches the swap file, which is there only because zswap needs a device behind it. A page that doesn't compress stays in the desk's memory against its cap, so a desk past its cap and its compressed share meets its own OOM killer, as with swap 0. What changes from swap 0: a desk's cold pages compress inside its own cap instead of being killed for (`spikes/desk-memory/`: swap 0 lost 8 tabs in test 5's soak; zswap lost none). The cost to the wall: the compressed pool's allocator is one for the host, though each object is charged to its desk. Proven on the host image: `spikes/shared-host-wall-3/README.md` (`WALL-07`).
  - `io.max` on every device it touches, its volume's and the root store's (`RC-04`, run 3): 0.8 of the instance's EBS baseline ÷ `DesksPerHost`, split four ways because `io.max` caps each device's reads and writes apart (`IO_SPLIT`: the root's reads 40%, its writes 10%, the volume's reads 25% and writes 25%), so six desks each at every cap use exactly 0.8 of the baseline. At 6 on an `m7g.xlarge` (156.25 MB/s, 6,000 IOPS): a root reads at 8.3 MB/s and 320 IOPS and writes at 2.1 MB/s and 80 IOPS; a volume 5.2 MB/s and 200 IOPS each way. Measured on the host image: `spikes/shared-host-wall-3/README.md` (`RC-04`).
  - Its root copy under a project quota, blocks and inodes, with `PROJINHERIT` set at preparation; a user namespace can't change a project ID.
  - A connection limit: 4,096 new-and-live connections inside its own namespace (the host's rule there) and 4,608 in the host's forward path keyed by its veth, the authority. `nf_conntrack_max` is `DesksPerHost` × 4,608 plus a reserve, 65,536 at 6 or fewer. The slot report carries each desk's count. Six real tabs reached 366.
  Proven: one desk at its memory cap 46 times, saturating both its devices and holding 4,096 connections for 140 s left a neighbour's video at 59.4 fps against 59.5 alone.
  Each desk's `/data` is its own volume, with its own size and IOPS (section 5). `desk-host` passes each desk's output to the host's journal under its desk ID, with a rate limit per desk.
- **The host never trusts or writes a path a desk controls (`WALL-03`).** It writes nothing in a desk's root copy or volume once the desk has run on it: what it gives a desk (the port, the shaper's profile and state, counters) it writes in a host-owned directory per slot, mounted read-only into the desk (`/run/desk-host`, `/run/desk-egress`); `desk-init` and its files are a read-only mount from the host too, so a desk's root can't change its own init. The one write into a desk's tree is the format record on a volume no desk has run on. Every read (the pairing code, the format record, the profile's `Last Version`) opens from a directory descriptor with `openat2`, `RESOLVE_BENEATH`, `RESOLVE_NO_SYMLINKS`, `RESOLVE_NO_MAGICLINKS` and `RESOLVE_NO_XDEV`; a write, were one ever needed, by an `O_EXCL` temp file, `fchown` and `fchmod` on its descriptor and `renameat`. Proven: links a desk's root planted get ELOOP, a path out gets EXDEV, a desk's write to the host's directories EROFS. No socket from a desk reaches host root. **`RC-01`: the rule covers everything the host hands runc** (section 2): roots, namespace files, `/run` directories and `/data` directories are the host's, or clones resolved without links; proven by planting absolute links at `/opt/ma/<svc>/current`, `/data/agent` and `/data/notebook` (and trying `/run/desk-agent`, a mount the desk can't remove) and starting the desk again. **`RC-06`: a read** opens `O_NONBLOCK`, takes only a regular file of at most 64 KiB and runs under a timeout, one slot at a time: a FIFO and a 4 GB sparse file at the pairing code's path were refused in 15 ms.
- **Nothing the host runs enters a desk (`WALL-02`).** `desk-host` uses `runc create`, `runc start` and `runc kill`. It enters only a created desk's network namespace, with its own `ip` and `nft` from the host's root, before any desk process has run. Never `nsenter` into a desk's user, mount or PID namespace, never `chroot` into its root, never `runc exec`. The one entry into a desk's mount namespaces is section 5's `mounts.py`: `setns` and `move_mount` from the host's own user namespace, after `runc create` and before `runc start`, opening each target with `RESOLVE_IN_ROOT` and no links. Proven: every process of both desks (26 each) carried `no_new_privs`, seccomp and the slot's profile (31 and 29 with the sandboxes, run 2). **`runc` is pinned at 1.5.2**, upstream's signed static build, by its SHA-256 (`d10ecae8...b46b0`) and its signer (`C2428CD7...A1100E`), checked by the host's own check. Debian 13's `runc` is 1.1.15+ds1-2, which Debian's security tracker lists as vulnerable to the November 2025 fixes (CVE-2025-31133, -52565, -52881; upstream fixed them in 1.2.8, 1.3.3 and 1.4.0) with no DSA and no trixie-backports package, and to CVE-2026-41579 (a `/dev` link in a container's root, fixed in 1.3.6, 1.4.3 and 1.5.0, "not exploitable under Docker" but a desk's root is exactly such a root). So the floor is 1.3.6, 1.4.3 or 1.5.0, and the newest release is taken.
- **What a desk sees of the host's disks (`WALL-08`).** `/sys/block`, `/sys/class/block`, `/sys/class/nvme`, `/sys/class/nvme-subsystem`, `/sys/fs/ext4`, each CPU's `cpuidle`, `/proc/partitions` and `/proc/vmstat` are masked, and from run 2 `/sys/dev/block` and each NVMe controller's own directory under `/sys/devices`, which the re-read found still listed the per-device counters; a desk lists none of them. `/proc/stat` stays (section 11). Each desk has `RLIMIT_CORE` 0, hard, and the host a discarding `core_pattern` (`IN-11`).

### 4. Identity (agreed)
**Platform** treats a shared-host desk like a self-hosted one for identity, with `hosting: "shared"`: it pairs the desk's key and mints short sessions of a per-desk role. Only for identity: `selfhost.md` §4 turns off idle stop, the cost guard, snapshots, backups and the Personal or Work count for self-hosted desks, and a shared-host desk keeps all of them, as a cloud desk does.

**The host** never lets its own credentials reach a desk:
- IMDS answers only uid 0 on the host, and its hop limit stays 1.
- Every desk's packets to `169.254.169.254` are dropped on the host (test 2's rule, proven).
- Inside each container, `ma-selfhost` stands in for the metadata service, with the same code as on self-hosted desks. Its Ed25519 key is on the desk's own volume (`/data/selfhost/key.pem`, `0600`, its own uid). It signs the DTLS identity, and serves `deskd` its desk ID as the instance ID, its tags, its public address and 15-minute credentials.
- The desk can't put the metadata address on its loopback without `CAP_NET_ADMIN`, so `desk-host` does it.

**New: pairing with no member typing a code.** The stand-in asks `pair` as a self-hosted desk does (`selfhost.md` §1). Where a self-hosted desk prints its code, this one also writes it in its own `/run` directory. `desk-host` reads it and carries it in its slot report, and Platform claims it for the desk it placed in that slot. A desk can pair only into its own slot. A desk moving in from an instance of its own pairs on its first start and is claimed for its existing desk ID.

**The host role reports slots, and nothing else.** Section 5 has Platform attach and detach volumes, so the host needs neither. If Platform keeps attach and detach on the host role, they must be scoped to volumes Platform assigned to that instance: a host that could attach any volume in its zone could read any member's disk.

### 5. Volumes (agreed)
Platform makes each desk's data volume with the tag `DeskId`, attaches it, and writes the host's tag `DeskSlots` = `1=d-…/vol-… 2=…`. `desk-host` reads `DeskSlots` through IMDS at boot and on every attach, and finds each volume by its NVMe serial, which is the volume ID, never by device name. It acts only when the device and the tag agree; a device the tag doesn't name within 60 s stays unmounted and is reported.

Per volume, exactly as `desk-firstboot` does today: format only if blank, write ADR 0035's record `/data/.ma-volume`, and report a format, so Platform can alarm on a desk that wasn't new.

**New:** the volume keeps the desk's own uids on disk, as on a desk of its own, and is mounted into its slot through a Linux idmapped mount. So the same volume works in any slot, on any host and back on an instance of its own, with no `chown`. Test 2 used a directory with shifted owners, and so did run 1. Run 2 built it (below).

**The raw filesystem never meets the host's users (`WALL-05`).** `desk-host` mounts a volume with `fsopen` and `fsmount`, sets `MOUNT_ATTR_IDMAP` with `NOSUID`, `NODEV` and `NOEXEC` on the detached mount with `mount_setattr`, and moves it straight into the container's mount namespace, so no raw mount is ever attached in the host's namespace. Its own work on a volume (the format check and record) runs in a private mount namespace, `nosuid,nodev,noexec`. No host process runs with a desk's in-image uids (0, 1100 to 1109). **Built and proven in run 2 (`mounts.py`):** in a mount namespace of its own, it formats a blank volume and writes the record and the services' directories through the fresh mount's descriptor, with the desk's own on-disk owners; then `fsmount` with `NOSUID|NODEV|NOEXEC` and `MOUNT_ATTR_IDMAP` to the desk's user namespace; it attaches the mount only in that private namespace, because on this kernel `open_tree()` can't clone a detached mount; clones the whole volume for the desk and each service's directory (section 2), and moves them into the desk's and the sandboxes' namespaces. `runc`'s own idmapped bind mounts need a source attached in the host's namespace, so `desk-host` doesn't use them. Proven: the volume's device is in no host process's mounts; in the desk `/data` is `idmapped,nosuid,nodev,noexec`; `/data/browser` is 1102 in the desk, 166,638 through the host's view of it and 1102 on disk; a program copied to `/data` won't run. **The same volume in another slot, with no `chown`:** desk 1 started in slot 2 (its root prepared again for it), `/data/browser` was 1102 in the desk, 232,174 from the host (slot 2's range) and 1102 on disk, and its cookies were in its profile there; back in slot 1 the probe's page found its cookie and `localStorage` again (`results/run2/proof-slot-move.log`; the probe's page is served from each slot's own address, so in slot 2 the cookies were read from the profile). Run 1 mounted each volume `nosuid,nodev,noexec` under a root-only path instead.

**Volumes from a desk's own instance (`WALL-09`, Platform's):** a volume whose blocks a desk's own root could write is a filesystem image the shared kernel would parse. Platform moves such a desk by file-level copy through a throwaway helper into a fresh volume, never by attaching the old one to a shared host (Platform's section owes the text).

`DeskSlots` fits a tag value's 256 characters only up to 6 desks (39 characters a slot with its space), while ADR 0101 allows 2 desks per vCPU. One tag per slot (`DeskSlot1`, …) would scale: Platform's call.

### 6. Addresses and ports
**Each desk keeps a public IPv4 of its own, on 443,** as test 2 ran it (proven): one secondary private address per slot on the host's interface, with the desk's Elastic IP on it. `desk-host` DNATs UDP and TCP 443 on that address to the desk, and sends everything the desk sends out from it. Slot k is the k-th secondary address in numeric order. `desk-host` reads the desk's public address from IMDS's association for it and hands it to the stand-in. So `deskd`'s `configure`, the two 443 candidates in `desk-endpoint.md` §3 and the gateway don't change: the answer's candidates are all a client needs.

Not one address per host, because:
- The landing page promises "a public IP address for every included desk", and the Terms give each desk one.
- ICE-TCP on 443 is the fallback for networks that block UDP, and only one desk per address can have it.
- Websites would see four members at one address, and one member's abuse would bring challenges on the other three. That's why test 2 gave each desk its own.
- The address can move with the desk (section 12).

It needs the account's Elastic IP quota raised (test 3), which is Platform's call.

**If the owner drops the address per desk,** the port setting does most of it. `desk-host` writes `port=` 4430 + k into the slot's own `/run/desk-host/desk-rtc.conf` (task 35's setting, `desk-rtc` 0.3.5), never into the slot's root (`WALL-03`): the template's `/etc/ma/desk-rtc.conf` is a link to it. It DNATs that port on the host's one address, and the desk's firewall gains a port define as the self-hosted one has (today's accepts and classifies only 443, `IN-08`). The answer's candidates carry the port, so the gateway and the Desk app learn it with nothing new: self-hosted desks already prove a port other than 443 end to end. The security group opens the slot ports, and TURN, when built, must allow them. The cost is the three points above, and a change to the Terms.

### 7. Stop and wake (agreed)
**The host** stops a desk by signal only (`WALL-02`): `runc kill TERM` to `deskd`'s container, then to the desk's, whose `desk-init` closes it as `desk-browser-close` does on a desk of its own: `deskd` already stopped, so nothing can start Chromium again (a `units.sock` start in flight finishes, later ones are refused); then Chromium is asked to quit over CDP (`Browser.close`, as `desk-browser-close` does since the image review's fixes) and gets SIGTERM with 30 s after it, writes its session and marks its exit (ADR 0035); then `sync -f /data`. The host waits for the container to stop, unmounts the volume and reports the slot stopped, so a snapshot or a detach after it is clean. A host shutdown, the cost guard's included, stops every container this way before the OS goes down (`IN-09`). A wake starts the container on the same slot root when its record names the desk (section 10), with nothing to copy.

**Proven in run 2 (`RC-05`):** `desk-init`'s close sends `Browser.close` over CDP as the desk's root and waits up to 31 s before SIGTERM, as `desk-browser-close` does: a desk with Chromium running stopped in 4 s with `quit=cdp` and `exit_type Normal`, and a cookie and `localStorage` set 40 s before and a cookie set 8 s before the stop were all there after a start. With the sandboxes, `deskd`'s goes first, then the desk's, then the other four, and the stop ends with section 10's reset of the slot. **Run 1:** a desk with Chromium running stopped in 2 s with `exit_type SessionEnded`, and after a start on the same root a cookie and `localStorage` set 40 s before the stop were there; `deskd`'s hello came 3 to 5 s after `runc start`. A cookie set 8 s before the stop was lost: Chromium commits cookies about every 30 s (TD-110). `main`'s `desk-browser-close` quits Chromium over CDP (`Browser.close`) first, which kept such a cookie on the test desk, and from run 2 `desk-init`'s close does too.

**Platform** runs the idle sweep per desk, stops the host only when all its desks are stopped, and takes the final snapshot of each desk's volume.

**New:** the host takes its orders (start a slot, stop a slot) on one outbound link to Platform, made with its host role, which also carries its slot reports. Platform's section defines it. No remote root command reaches a host, for ADR 0091's reason four times over.

### 8. Bytes, the shaper and the cost guard (agreed, with one correction)
`desk-host` counts every byte each desk's container sends out of the host, in the host's forward path, which the desk can't touch, keyed by the slot's veth and after the rule that drops any packet without the desk's own source. It writes `{bytesOut, bytesIn, boot}` to the desk's `/run/desk-host/net.json`; `boot` is new at each container start, when both counts start again at 0.

**What is counted (corrected 2026-11-09, `sub/host-wake-counters`).** `out_<k>` is every IP byte the desk sends out of the host and `rx_<k>` every IP byte it receives, in both directions of every flow. The forward chain used to accept `ct state established,related` before it reached the slot's chains, so `out_<k>` saw only each new outbound flow's first packet and nothing of a desk's media (replies on flows that came in through its DNAT): a free desk that had streamed video for minutes showed 188 packets. The chain now jumps to `desk_est` first; `est_<k>` there counts both directions with no verdict, and the same accept follows, so the fast path and every drop are as they were. Packets the wall drops are never counted here. A new flow's first packet is counted where it is accepted (`slot_<k>`, `fwdin_<k>`). The count is the IP length, so it is within the veth's own byte counters by the 14-byte Ethernet header per packet (a 60 s 1080p60 stream: 0.985 of the veth; a 9.6 MB download: 0.999). `desk-host-check counters` fails a host whose count comes after the accept or whose slot lacks its counters, and `verify.sh` breaks it on purpose. `deskd` puts it in its heartbeat as `net`, and Platform's cost guard counts per desk from it.

**The correction:** ADR 0036 §3 says a compromised `deskd` "can lie in its heartbeat, so no traffic stop reads the heartbeat". So the heartbeat's count slows and flags a desk, and the last-resort stop stays on the host's own `NetworkOut`, with ADR 0036's limits times `DesksPerHost`. The slot report carries the same counters, so Platform sees a desk whose heartbeat falls short.

**ADR 0036's shaper, per container (new):**
- `desk-host` puts the HTB classes on the desk's end of its veth, inside its namespace, and the `classify` chain sorts by the desk's own uids, as it does on `ens5` today.
- `desk-egress`'s budgets run on the host, one per slot, and their state stays on the host, under `/var/lib/desk-host`, keyed by desk ID (`WALL-03`: a host write into the desk's `/data` would follow a link the desk planted). A move starts the bucket again on the target, and the guard still counts.
- The profile reaches `desk-stream` through `/run/desk-egress`, mounted read-only from the host, and `desk-init` restarts `desk-stream` when it changes.
- Four desks at their ceilings send 648 Mbit/s, well inside a `c7g.xlarge`'s baseline (not read here; a `c7g.large`'s is 0.937 Gbit/s, ADR 0036), so `ens5` needs no shaper of its own.

The Agent filter ran inside the wall in the wall test, with a stub resolver in place of `systemd-resolved` (the providers answered 401, `www.cloudflare.com` was refused); the teen lock hasn't (new). `desk-browser-policy` runs as the desk's root before every start of Chromium, reads `/data/desk/age-band` and writes the lock into the slot root, where only the desk's root can change it. ### 10. First open: `desk-preread` on a shared root
Each slot's root is the desk's own copy of the image's desk root, so no two desks share a page of memory (test 2's defence against Flush+Reload). A copy isn't restored from a snapshot, so EBS's first-read cost, which `desk-preread` exists for, falls on the host's copy step instead. The first copy reads the image's desk root whole, once, from the cold snapshot, and every copy is freshly written. `desk-host` leaves `desk-preread`'s stamp in each copy, so it never runs in a desk.

**The template (`WALL-04`)** is the image's own desk tree, baked at build, never booted, host-owned and read-only on the host: never the host's live root. `verify.sh`'s host section checks it holds no cloud-init state, host keys, host logs, authorized keys, machine ID, slot records or `desk-host` config.

**A slot's root belongs to one desk, by a record the desk can't touch (`WALL-04`).** When `desk-host` prepares a root for a desk, it writes `/var/lib/desk-host/slots/<k>.json` on the host's own root, outside the copy: the desk ID, the template's version and the time. It starts a desk only on a root whose record names it (a wake, which keeps the root). Anything else (another desk, no record, no root, a record left by a crash mid-preparation) re-prepares the root from the template synchronously, before the new desk's volume is mounted, and refuses to start if that fails. The record is removed first and written last, so a preparation that stops half way leaves no record and the next start prepares again. A new root is built beside the old one, swapped in by rename, and the old one removed with a delete that follows no links and stays on its filesystem. A new host prepares its slots before it reports ready, and a slot whose desk left is prepared again in the background as well, so the next start usually finds it ready. Proven: a desk's edit to its root stayed through its own wake and was gone when another desk took the slot; a preparation with no template refused, with no container started; the template passed all 8 checks.

**Slot states (`RC-03`, built and proven in run 2).** A record has two states: `fresh` (prepared from template T, never started) and `desk` (claimed by one desk ID). A preparation, in the background or on demand, writes `fresh` last; a start claims a `fresh` root of the current template by rewriting its record to `desk` before `runc create`, wakes a root whose record names its desk, and prepares anything else again first. A preparation first removes whatever an earlier one left half done, and checks every step, so it fails closed even where the caller doesn't stop on errors. **Every stop resets all of the slot's state outside its root** (containers, the whole cgroup tree by `cgroup.kill` and depth-first removal, `/run/desk-host/<k>`, the namespace binds, the shared tmpfs, the slot's nft chains and its jumps, its conntrack entries, its veth and its AppArmor profile), and a start refuses a slot where any of it remains. Proven: desk 2's root made nested cgroups (17 directories under its slot), and after its stop none was left; a preparation killed after its copy, and one killed after its rename, left no record; a veth left with the slot's name refused the next start; a background preparation wrote `fresh`, and desk 3's start claimed it with no second copy. **Found on the way:** the first gate run filled the slot store, because the two killed preparations left their trees and the next one, called as `prepare || refuse` (where `set -e` doesn't apply), went on past a failed copy and claimed an empty slot. Fixed as above, and the run repeated (`results/run2/proof-rc03*.log`).

**A cold wake reads from the host's side first (2026-11-09, `sub/host-wake-counters`).** A wake after the host's page cache has gone cold (a busy hour) reads the desk's Chromium, `deskd` and the other services' release copies through the desk's own root-read share. Measured on an `m7g.xlarge` with the cache dropped: a free desk took 71.6 s to `deskd`'s hello and 184 s to a Browser that answers CDP; a standard desk 30.5 s and about 85 s. `desk-host up` now starts `preread.py` beside the rest of its start. It reads, from the host's side, the files and byte ranges in `/etc/desk-host/preread.list` (made from a read trace of a cold wake: 450 MB of the 580 MB a free desk read), so the pages sit in the host's page cache charged to no desk. It runs in its own cgroup beside `desk-host` with `io.max` at 0.2 of the EBS baseline; the desks' caps sum to at most 0.8, so it takes only what nobody holds, and no desk's cap changes. The start waits for the first part of the list (deskd, the base libraries, the other services: 177 MB, 5.7 s); Chromium's part is read beside the running desk. The list holds regular files by path inside the slot's root or release copies and never follows a link. A class may also carry its own `IO_SPLIT` (section 16): `free` gives root reads 70% of its disk share (5.8 MB/s of 8.3, from 3.3), because a cold free desk's remaining reads go through that share. Result, 3 samples each: standard hello 19.1 to 19.4 s and CDP 34.9 to 35.8 s; free hello 23.5 to 23.8 s and CDP 42.1 to 42.3 s (`spikes/host-wake-counters/README.md`).

A first open in a slot is then today's warm open: 2.8 s to Chromium's port and 3.6 s to the page on a t4g.medium; in the wall test the first picture came 5.0 s after `live` on a fresh root. Preparing a root (3.0 GB) took 21 to 24 s on a quiet `c7g.xlarge` and 44 to 49 s beside running desks.

### 11. What a member notices when a neighbour is busy
- **Idle neighbours:** nothing. 59 fps and about 100 ms input to frame at p95, as on a desk of its own (test 2).
- **Test 3's realistic peak,** two members watching video while two read on one `c7g.xlarge`: one flick in 109 ran at 29.98 fps, the video's worst 5 s held 33.8, and input to frame was 138 ms at p95. Smooth, a little coarser: ADR 0071's known edge.
- **Everyone scrolling at once:** the page held 31 at its worst 5 s and 37.5 on average, with 234 ms of input lag, visibly laggy to type into.
- **The picture stays whole.** The stream keeps 55 fps or more, because inside each desk the encoder outweighs Chromium 4 to 1, so a member sees fewer new frames, not a broken picture.
- **What would go under 30,** not measured: a third video at once, an Agent at work, faster readers. The lever is `DesksPerHost` on new hosts; at 3, every realistic load held 40.
- **What a neighbour's code can learn (`WALL-08`):** timing and activity, never content. `/proc/stat`'s CPU, interrupt and softirq lines are machine-wide, so code running in one desk can tell when another starts and stops heavy work such as a video. Published work has inferred keystroke timing and visited sites from such signals, and nothing here rules that out. The sysfs paths that named each neighbour's disk and its activity are masked (section 3). LXCFS isn't adopted: it wouldn't hide sysfs, and it would be a host-root daemon answering every desk's reads. Member-facing wording leans on "timing and activity, not content", not on "never".
- **Memory, under the wall (`WALL-07`):** a desk can't park pages in the host's swap outside its cap: with run 3's memory rule (section 3) its cold pages compress into its own cap, so its cap is all it has. At 6 per `c7g.xlarge` (1,189 MiB a desk) with swap 0 the wall test's desk with six real tabs and a video lost two tab renderers to its own OOM killer; test 5 and the memory study then moved the packing to 6 per `m7g.xlarge` (2,507 MiB a desk on the host image) with the rule. **On the host image (run 3), six real desks at the realistic peak:** no OOM kill, no desk at its cap (peak 1,774 of 2,629 MB), nothing swapped, every unseen desk's six tabs kept through its freeze, in 3 runs of `peak-frz`; and over a 34-minute soak with six real tabs in every desk (24 videos, lowest 5 s window 51.8 fps; 315 flicks, p5 51.9; input p50 58.9 ms; peaks 2,171 to 2,366 of 2,629 MB, nothing swapped, no kill). The rule was not exercised by that load; `WALL-07` on the image drives it on purpose (`spikes/shared-host-wall-3/README.md`).

### 12. Moving a desk between hosts (new)
Platform runs a move while the desk is idle (13.2's meaning), within one zone:
1. **Preflight, per desk:** the target image's Chromium is at least the profile's `Last Version` (from the desk's heartbeat, a new field), the target's image has `DeskTeenLock=1` if the desk is a teen's, and the target has a prepared slot.
2. The source stops the desk (section 7) and reports it unmounted. Platform snapshots the volume, detaches it, moves the desk's Elastic IP to the target slot's address and attaches the volume there.
3. The target finds the volume by its serial, checks its format record, prepares the slot's root for the desk if the slot's record doesn't name it (section 10), mounts the volume into the slot and starts the desk. `desk-browser-start`'s guard still refuses an older Chromium (exit 78, profile untouched), so a wrong preflight costs a Browser that waits, never a session.

The desk keeps its key, DTLS identity, session, address and desk ID, so nothing pairs again, and sites that tie a sign-in to an address don't notice. **What it leaves behind (`IN-11`), each with an owner:** its old slot's root, prepared again before the slot is offered (System, section 10); its lines in the old host's journal, purged within 24 hours of its leaving (System); an old volume after a cross-zone move, or an old instance and its role after a move in from one, tagged with the move and expired by an owner-approved step (Platform). It runs the target's baked releases, as after a root swap, and takes later ones forward (runtime spec §6). Across zones a move is a snapshot and a new volume, whose first reads are slow, so Platform does it while the member is away. Downtime is unmeasured; the study guessed 30 to 90 s.

### 16. Container sizes by tier (S-119, the free tier; 2026-11-09)
The owner, on the free tier: "Just like other tiers, multiple users will have to share an EC2", "I don't want an EC2 to just be free tier specific. The tier just decides the container size and how much is allotted", and "we are betting on not every free user to be online at the same time and if they are then they will just experience some slowness". For paid desks: "Its okay if sometimes people get less than 60. Below 30 is unacceptable".

**A slot's class sets its container's size.** `/etc/desk-host/classes.conf` (host root's) lists classes, each value a multiple of one standard desk's share of the host, where a host holds `DesksPerHost` standard desks:

| Value | What it sets | A unit is |
|---|---|---|
| `cpu` | `cpu.weight`; 0 is the kernel's `cpu.idle`: the desk gets only CPU no other desk wants, and another desk's waking thread takes it at once | 100. No class has a CPU cap |
| `memory` | `memory.max`, firm | (`MemTotal` − 640 MiB) ÷ `DesksPerHost` |
| `swap`, `zswap` | the memory rule's `memory.swap.max` and `memory.zswap.max`; `memory.zswap.writeback` stays 0 for every class | `DESK_SWAP_MAX` (2 GiB), `DESK_ZSWAP_MAX` (1,000 MiB) |
| `disk` | `io.max` on its root and its volume, split by `IO_SPLIT` or the class's own split (the table's optional 8th column: `free` is 70, 5, 12.5, 12.5). Admission sums all four byte caps of every desk to 0.8 of the baseline, so a split changes who gets the share, never the total | 0.8 of the EBS baseline ÷ `DesksPerHost` |
| `pids` | `pids.max` | 8,192 |
| `egress` | ADR 0036's rates, published in the desk's `/run/desk-host/class.json` | a desk's (60, 2 and 100 Mbit/s) |

`standard` is all 1s and is every slot's share before classes, to the byte; a slot with no class is `standard`, so a 0.1.4 or 0.1.5 host and Platform's 2- and 5-field tags behave exactly as before. Connection limits and the root's quota stay the same for every class (a live change would have to enter the desk's network namespace, which section 3 forbids while it runs).

**Admission, so paid desks never pay for free ones' peaks.** `desk-host` starts a desk, or raises a running one's class, only while the running desks' `memory.max` and disk shares, read from their cgroups, stay within `DesksPerHost` standard desks' (a host-wide lock around the check and the write). Memory is firm per desk and the sum of every running desk's cap is never more than `MemTotal` − 640 MiB, so no desk's peak can take memory from another and the host's own OOM killer has nothing to choose between desks: a free desk past its cap meets its own OOM killer, as any desk does. A start past the host's units is refused with exit 75 and nothing created, and Platform places the desk elsewhere. CPU is the one thing shared without a cap: a free desk is `cpu.idle`, so it runs only on CPU no paid desk wants and a paid desk's waking thread takes the CPU from it at once; when the host isn't busy, a free desk gets all the CPU it asks for. A weight of a tenth of a paid desk's wasn't enough (measured below), and since CPU has no cap, how many free desks may *run* at once beside paid ones is a placement rule (Capacity, below), not something admission enforces.

**An upgrade in place.** `desk-host class <k> [<class>]` rewrites a running desk's cgroup: `cpu.weight` (or `cpu.idle`), `pids.max` and the memory rule's allowances at once, then `memory.max` and `io.max` on both devices. Nothing in the desk restarts, nothing enters it, and its Browser keeps its pages, cookies and storage (measured below). A raise of memory or disk is admitted as a start is; when the host has no room for it yet, the desk keeps its memory and disk share, has the paid CPU weight and limits already, and the raise waits (`pending` in its record, exit 75) until `desk-host class <k>` runs again after a neighbour's stop has made room; its next start takes the class whole. A lower `memory.max` is written only when the desk's `memory.current` is at most 90% of it, so the kernel needn't reclaim or kill to meet it; otherwise it waits for the desk's next start. Platform makes the wait rare by keeping one upgrade's room on hosts with free desks.

**Slots and units.** `DesksPerHost` stays the host's size in standard desks. A new launch tag, `SlotsPerHost` (proposed to Platform; `DesksPerHost` to 29, `DesksPerHost` when absent), says how many slots a host has: with free desks it holds more desks than units. Each slot's source-port block and the host's conntrack table follow the slot count.

**`free`, measured (2026-11-09, `spikes/host-size-classes/README.md`):** `cpu` 0 (`cpu.idle`), `memory` 0.4, `swap` 1, `zswap` 0.5, `disk` 0.4, `pids` 0.5, `egress` 0.5: on an `m7g.xlarge`, 1,052 MB, 4,096 tasks, root reads 3.3 MB/s. On one `m7g.xlarge` from host image 0.1.5 with these files copied on, five free desks of 0.30 to 0.50 units each read a long page with three ordinary tabs behind it: 0.40 is the smallest where the Browser holds up (flicks p5 52.5 fps, tabs loading in 1.8 to 4.6 s, 120 MB compressed inside its cap, no memory stall, no OOM kill). At 0.35 the page still scrolls at 44.9 once loaded, but the desk thrashes while pages load (8 to 29 s a tab), and at 0.30 a page didn't load in 45 s and Chromium's own start check timed out. Alone with its neighbours idle, the free desk played the 1080p60 clip with three tabs open at 59.0 fps in its lowest 5 s window, input to frame 57.0 ms at p50, at its cap with 198 MB compressed inside it and no OOM kill: its CPU share (`cpu.weight` 10 in that run) costs nothing when nobody competes. Chat has no desk-side service yet (the app is an empty state); the Agent's calls answered on the free desk and a key's round trip to its provider through the Agent filter came back in 2.65 s. **An upgrade in place, measured:** `desk-host class 6 standard` under a playing Browser took the cgroup from free's values to standard's at once, with all 34 processes kept, the same browser process, the page's state, cookie and storage kept, and the stream at 59.9 fps before and 60.0 after with no stall; back to free the same way. **A cold wake is slow:** with none of its root's pages cached, the free desk read 582 MB through its 3.3 MB/s root share and took 69 s to `deskd`'s hello and about 3.5 to 4 minutes to a ready Browser (a standard desk as cold: 29 s and about 1.5 minutes; a free desk's wake 9 minutes after a stop: 24 s to the hello), a follow-up before free desks wake often.

**At the peak** (2 `standard` desks beside busy free desks; paid desks judged by what 6 per `m7g.xlarge` held in wall 3: video lowest 5 s windows 57.3 fps, flicks p5 53.3, input p50 under 71.2 and 62.3 ms): with 10 free desks busy at `cpu.weight` 10, the paid desks missed it (49.9 fps, flicks 47.7, input 72.2 ms), never near 30; with the same 10 at `cpu.idle` they held it (58.0, 54.0, 59.3 ms), and so `free` ships `cpu.idle`. Either way the ten free desks froze (0 page fps, input p50 0.3 to 0.6 s, streams with no new frame in 79 to 87% of tenth-second samples): twelve busy desks on 4 vCPUs is overload, and no weight fixes that, it only decides who pays. With 4 free desks busy at `cpu.idle`, the paid desks held the floor (57.8, 53.7, 56.5 ms) and the free desks kept moving, slowly: the clip at 29 and 32 page fps on average with lowest 5 s windows of 12, a reader's flicks at 21 to 23 fps at the median and 10 at p5, keys showing in 145 ms watching and 63 to 75 ms reading, tabs loading in 1 to 8 s. No OOM kill on the host in any run, and zswap wrote nothing back. **So a busy free desk takes a whole running place: a host runs at most `DesksPerHost` desks of any class at once**, a placement rule (CPU has no cap and admission counts memory); the free class's smaller memory doesn't add running desks, it makes the paid desks' memory untouchable and the overcommit is in desks assigned and stopped.

**Capacity, for placement** (`m7g.xlarge`, `DesksPerHost` 6): running free desks at once beside 0 to 6 paid ones, 6, 5, 4 (measured), 3, 2, 1 and 0; desk-host's own memory limit is higher (14, 12, 10, 7, 5, 2, 0 within 14 slots), and the gap is room for running free desks that are idle, which costs paid desks nothing but freezes every free desk if they all turn busy. A stopped desk holds no memory, CPU or disk share, so overcommit is in assignment: no number of assigned free desks can make OOM touch a paid desk (admission refuses the wake instead) or take its CPU (`cpu.idle`), and what it costs is a wake that starts elsewhere; at 2 paid desks and 4 free places, about 14 free desks a host if a tenth are on at the busiest minute, 26 if a twentieth (`spikes/host-size-classes/README.md` section 6). Overcommit past `SlotsPerHost` needs a stopped free desk to give its slot back (its root holds nothing of its member's), which is Platform's.

**Cost (for Platform):** a free desk's container costs host time only while it runs, 30 to 60 Browser minutes a day (a running place for each running hour). Its public IPv4 costs several times as much when it's billed while the desk is stopped (and contract 0.3.33 fixes each slot's address, so it is), so the address, not the host, decides how many free desks a budget holds. Section 6's fallback, one address per host by port (not built), saves all of it; the stream itself, 49 to 97 GB a month at normal quality, costs more than either (`spikes/host-size-classes/README.md` section 7).

## Platform's side

**Status:** Proposed by the Platform Engineer (task 46), 2026-11-07. Nothing is built or switched on: `ma-platform` `terraform/shared_hosts.tf` is off (`local.shared_host_envs` and `local.shared_host_port_envs` are both empty). Packing: `ma-platform` ADR 0101 and its addendum.

### P1. Addresses: one per desk, kept; address plus port waits on the owner
**Kept, as section 6 says:** each desk keeps a public IPv4 of its own, on 443. Platform assigns slot k's secondary private address on the host's one interface (the k-th in numeric order, as section 6 reads it) and associates the desk's Elastic IP before it orders the slot started. The interface carries `ma-desk-template`, the group every desk has today: UDP and TCP 443 in, from the 16 CIDRs that make up 0.0.0.0/0 minus the VPC CIDR. So `ma-platform` ADR 0036's block between instances, the subnet's NACL, the contract and the gateway are all unchanged. The host's own primary address is auto-assigned at launch, for the host's own traffic.
- **An Elastic IP's life:** allocated when the desk first starts on a host, kept while it runs and through a move (section 12), released when the desk stops, and a new one at its next wake. So the address changes at each start, as a desk's does today (`ma-platform` ADR 0014), and a stopped desk costs nothing for it. Keeping it while stopped would bill the address for every stopped month: the owner's call if a steadier address is wanted.
- **Limits:** the account's Elastic IP quota must be raised; Platform asks for the running desks planned, plus headroom. An interface takes 15 IPv4 addresses on the xlarge and 2xlarge sizes and 30 on 4xlarge, so with the host's own that's at most 14 or 29 desks a host, and `hosting#current` now refuses more (`ma-platform` `services/desks/src/hosting.ts`).
- **Platform's role** may assign and unassign secondary addresses and allocate, associate, disassociate and release Elastic IPs, on hosts it launched only. Releasing one is new to `ma-platform` ADR 0091's boundary, like a detach (P3).

**Address plus port, the option that needs the owner's word,** because it breaks the landing page's and the Terms' "a public IP address for every included desk": no address of each desk's own, which saves what those addresses cost. It's `local.shared_host_port_envs` in `ma-platform`, empty.
- **In:** slot k is UDP 4430 + k on the host's one address (section 6's port setting), DNATed by `desk-host` in the kernel: no copy, and no CPU per frame on the main path. Test 3 ran desks 5 and 6 this way.
- **What the 443 fallback becomes: one TCP 443 for every slot, through an ICE-TCP demux in `desk-host`.** Each slot's `desk-rtc` starts its ICE usernames with the slot's tag, set by `desk-host` as it sets the port (a `desk-rtc` change), and offers `<host address> 443 tcptype passive`. The demux listens on the interface address only, never on a slot's side; reads the first RFC 4571 frame; requires a STUN Binding request whose USERNAME starts with a live slot's tag; and splices the connection to that slot's own TCP port, keeping the browser's source address (transparent proxying), so `desk-rtc`'s per-source limits still see the real peer. Anything else is closed unanswered. It limits new connections per source (10 a minute, `desk-endpoint.md` §3) and logs no addresses. It sees what any router on the path sees: ciphertext and ICE usernames. Without the demux, the fallback becomes a TCP port per slot (4430 + k), and networks that allow only TCP 443 lose their desk; or, later, TURN on TLS 443 (`ma-platform` ADR 0075), a small box relaying to the slot ports over private addresses.
- **Out:** each slot SNATed to the host's address with a fixed block of source ports of its own (10000 to 59999 split by `DesksPerHost`: 8,333 each at 6), so an abuse report's address, port and time map to one slot and, through `DeskSlot<k>`'s history in CloudTrail, to one desk, with no flow or NAT logs (`/privacy`: "Our systems don't record which websites you visit").
- **Placement:** a member's Personal and Work never on one host, so no website sees both from one address.
- **Security group:** `ma-shared-host` in place of `ma-desk-template`: UDP 4431-4462 and TCP 443 from outside the VPC only (32 rules), out as the desk group. The wall adds two drops: the demux is unreachable from a slot, and new inbound reaches a slot only through its own DNAT or the demux.
- **Contract:** `desk-endpoint.md` §3 gains a shared-host exception (one UDP candidate at 4430 + k, one passive TCP candidate on 443, the slot's tag on ICE usernames), through the coordinator.
- **What members would lose:** the promise; a shared reputation (a site that challenges an address challenges every desk on that host); and `ma-platform` ADR 0014's exact egress per interface, which P7 replaces.

**Rejected:** IPv6 per desk with IPv4 browsers through a TURN relay in the VPC (a relay to run in each env, a hop, and IPv4-only websites still need the host's address); an NLB with a listener per slot (a balancer in each env and a charge per member, a hop, and still a port per slot); no address on the host at all (a relay for everyone and a NAT gateway billed on every byte each way). Never the kiosk's relay (`ma-platform` ADR 0086: AWS Service Terms 51.3).

### P2. Launch and tags

RunInstances adds the host image; the type from `hosting#current`, which must be on the allow-list (`c7g` xlarge to 4xlarge, `c8g` xlarge to 4xlarge, `m7g` xlarge and 2xlarge); a root of 10 GB plus 3 GB a desk (gp3, encrypted); the host role's profile; `DesksPerHost` and `HostingVersion` (section 1); `ProvisionedBy`; and `CostCenter=member` once it carries a paying member's desk.

**One tag per slot, in place of section 5's `DeskSlots`:** `DeskSlot<k>` = `d-…/vol-…`, written by Platform before it attaches that desk's drive and removed after it detaches it. `desk-host` reads `DeskSlot1` to `DeskSlot<DesksPerHost>` through IMDS at boot and on every attach, and acts only when a device's serial and its slot's tag agree, as section 5 says. At most 29 slot tags and about 10 others, under EC2's 50 a resource.

### P3. Volumes: Platform attaches, the host only reports (in place of section 4's and 5's attach)
Platform creates each desk's drive (`pricing#current` `deskDataVolumeGb`, 32 GB of gp3, `ma-platform` ADR 0094), tagged `DeskId` (and `DeskBackup=daily` for a real desk), writes `DeskSlot<k>`, attaches it, and detaches it only after the host's report says that slot is unmounted. **The host role never attaches, detaches or tags anything:** it reports slots. Platform's role may attach and detach only volumes it made (`ProvisionedBy`), to and from hosts it launched in its env, and may tag only `DeskSlot*` keys on them. Detach is new to `ma-platform` ADR 0091's boundary ("no role can detach"): the Security Analyst's and the owner's call. The final snapshot (`ma-platform` ADR 0092) and the daily backups stay per volume, as today.

### P4. Identity (agreed): like a self-hosted desk, for identity only
A shared-host desk's row has `hosting: "shared"`, and it proves itself as a self-hosted desk does: Platform claims the pairing code from the slot report for the desk it placed in that slot, only when the report comes from the host whose `DeskSlot<k>` names that desk, then mints the desk short sessions of its per-desk role. **That's all it shares with a self-hosted desk.** Idle stop, the cost guard, snapshots, backups and the Personal or Work count stay on, as for any cloud desk; `selfhost.md` §4 turns them off for self-hosted desks only.

### P5. The host's link (section 7 leaves it to Platform)
- **The host role** (`ma-<env>-shared-host`, its profile on hosts only): SigV4 to `/v1/host/*` on the agent API, and SSM's core. Nothing else: no EC2 write, no `settings` read, no KMS on members' keys, no desk role.
- **`POST /v1/host/hello`** at boot: the instance ID from the SigV4 session, as `/v1/agent/*` takes it, checked against EC2 (`HostKind=shared`, this env's `ProvisionedBy`), with the first boot's `DesksPerHost` and `HostingVersion` and any difference section 1 reports.
- **`POST /v1/host/report`** every 30 seconds and on any change: per slot its state (`empty`, `prepared`, `starting`, `running`, `stopping`, `stopped`, `unmounted`), the desk ID and volume serial it found, a format event, a pairing code, and its `{bytesOut, boot}` (section 8).
- **Orders ride the reply,** as `prepare_stop` rides a heartbeat's: `prepare_slot {k}`, `start_slot {k, deskId}` and `stop_slot {k, reason}`, each with a sequence number the host acknowledges in its next report, so a lost reply is sent again and a repeated one does nothing. Nothing reaches a host inbound, and no routine work uses SSM's run command.
- A report naming a desk its slot's tag doesn't is ignored and flagged.

### P6. Stop, wake and the host's own stop (agreed)
The idle sweep runs per desk (24 hours, 1 hour for test desks), and so does `connect`'s wake. A stop is a `stop_slot`; Platform releases the desk's Elastic IP once the slot reports stopped (P1). A wake on a running host associates a new Elastic IP and sends `start_slot`; on a stopped host it starts the host first, so that wake adds the host's boot (unmeasured). Platform stops a host only when every desk on it is stopped and no move is under way, and never terminates one.

### P7. Bytes and the cost guard (section 8's correction, kept)
**The last-resort stop stays on the host's own `NetworkOut`** (CloudWatch's, which no desk can touch), at the cost guard's limits (`ma-platform` ADR 0082: 30 GB in 15 minutes, 150 GB in 24 hours, 1,200 GB in a month) times `DesksPerHost`. It stops the host's desks through the real flow, then the host. **The per-desk counts only slow and flag:** the heartbeat's `net.bytesOut`, which a compromised `deskd` could fake, and the slot report's own counter pick the desk to slow or flag, and a heartbeat that falls short of the slot report flags that desk. The bandwidth meter (`ma-platform` ADR 0095) still counts each desk's `media.bytesSent`.

### P8. Placement and capacity
Placement fills a host up to its own `DesksPerHost` tag, not the current setting; puts a teen's desk only on a host whose image has `DeskTeenLock=1` (section 9); and, under address plus port, never puts a member's two desks on one host. Until placements are recorded, `ma-platform` ADR 0101's sales gate asks for a whole host per new member (4 vCPU on a `c7g.xlarge`, 16 on a 4xlarge); then free slots count.

### P9. Moves and drains (section 12)
Platform's mover: the preflight (the heartbeat's Chromium `Last Version`, the teen lock, a prepared slot), `stop_slot`, the unmounted report, a snapshot, the detach, the Elastic IP onto the target slot's address, `DeskSlot<k>` off the source and onto the target, the attach, `start_slot`. A host image change drains by moving desks at idle onto new hosts, or waits until all are idle; a kernel privilege escalation reachable from a desk is urgent (section 13).

### P10. What Platform's side leaves unproven
- Whether 6 desks hold 30 fps on any host: test 5.
- The link, the mover, placement, and the Elastic IP and address handling: none built.
- Address plus port's demux, slot tags in ICE usernames and port-block SNAT: none built. Chrome taking a public candidate on 4431 to 4462: test 3's 4435 and 4436 worked in Chrome 156, so likely.
- AWS's answer on the Elastic IP quota at members' scale.

## Alternatives rejected
- **gVisor** (test 1, `spikes/shared-hosts-gvisor/README.md`): about 1.8 times the CPU. It fails B11 and B12 on `m7g.large` and has no headroom on `m8g.large`, and inside one sandbox the unit weights don't apply, so the encoder loses to Chromium.
- **Firecracker, or a VM per desk.** Ordinary Graviton machines don't offer nested virtualization. Bare metal does, but it's a much larger machine and its volume limit caps it at about 14 to 38 members, so it costs far more per member than a shared host (`ma-platform` study, section 1). On x86 with nested virtualization the image moves to x86, cores are split as hyperthreads, and AWS warns that nested VMs suit latency-sensitive work less well.
- **One instance per desk:** today's setup, which costs far more per member than a shared host (ADR 0071), and the owner won't promise it.
- **systemd as each container's init, and Docker inside or beside:** section 2.
- **One public address per host:** section 6, kept as the fallback.

## Consequences
- Clients see nothing new: the same 443 candidates, the same pinned identity and the same hello, with `hosting: "shared"`.
- When built, `desk-runtime.md` gains a shared-host section, and Platform's `desk-endpoint.md` and `selfhost.md` gain `hosting: "shared"`.
- The update policy's 13.9 gap closes for the host side: service batches per desk, host changes drained by Platform.
- SSM on a host is root over every desk on it, so each member's access history lists every break-glass on their host.
- The app contract's unit sandbox (draft, section 8) rests on systemd and `mount`, which the wall doesn't give. Apps need their own answer before they run on shared hosts.
- **The wall costs memory at 6 per `c7g.xlarge`** (section 11): without zram outside the caps, a desk with many tabs meets its own OOM killer at 1,189 MiB. The packing waits on test 5's real-tab load at that share, or a kernel with zswap.
- **Before a member is placed:** the Terms call desks "private cloud computers, each its own virtual machine", and the landing page says "its own private computer" and "its own cloud computer". None of these holds on a shared host. The study's section 4 has wording, and a change to the Terms after launch needs 60 days' notice.
