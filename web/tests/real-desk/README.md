# Real-desk checks

Scripted Playwright runs against the real test desk on staging (`DeskKind=test`), run before a Desk app release goes to prod. They sign in as `desk-1` with credentials read from SSM, which are redacted from every log and never printed. They refuse to focus or wake anything but `<test-desk>`, and they fail if anything sends `start: true` unexpectedly. `rt-signin.mjs` is the exception, with its own account and no desk. Never point them at another account or at prod.

**A connected desk's label** is `online · …` until its `desk-agent` answers `agent.state`, and then that word (`no key`, `agent online`, and so on). `waitPanel(/online/)` takes any of them as connected, and `rt-lib.mjs` exports that set as `CONNECTED` (`rt-stage1.mjs` step 2 uses it).

**The layout follows the member** (`shell/layoutSync.ts`): with a bundle that has it, a script reads its account's real document at load and saves what it changes there, so a run on `desk-1` would start from where the last one left the desks. The scripts that depend on where the desks and apps are (`rt-stage1` to `rt-stage4`, `rt-stack`, `rt-desks`, `rt-hidden`, `rt-carousel`) pass `layoutStandIn: createLayoutStandIn()` to `openSession` (`rt-lib.mjs`): an in-memory `GET`/`PUT /v1/me/desk-layout` that starts never saved, so they start from a fresh layout and `desk-1`'s real document is neither read nor written. The run logs its calls and fails if one got past it. The rest (`rt-agent`, `rt-browser`, `rt-notebook*`, `rt-one-live`, `rt-simple`, `rt-sound-hidden`, `rt-watch`, `rt-wake`, `rt-csp-windows`, `rt-ice`) don't depend on the layout and still use the real document.

**The office tour (ADR 0056)** starts by itself on `desk-1` until someone presses Done or "Don't show this again", and while it shows the office is inert and the keyboard is the tour's. A script that drives the office by keyboard calls `closeTour()` (`rt-lib.mjs`) after `openSession`, which closes it with its own close button and writes nothing; `rt-csp-windows` does (release 19's run failed there without it). It returns once the layout document has been read and 5 s pass with no request for the tour's chunk.

Run from `web/` with Node 24 and AWS read access to `/ma/staging/test-users/desk-1`. Output and screenshots go to `test-results/real-desk/`. **Look at a screenshot**: passing checks have missed visual breaks.

```bash
MA_EXPECT_VERSION=2026.11.05-abc1234 node tests/real-desk/rt-stage1.mjs
```

## Agent tools: adding a tool

`rt-agent-tools.mjs` runs what `agent-tools/cases/index.mjs` registers: one file per tool, exporting `{tool, title, cases}`, and one line in `REGISTERED`. A case is what the member types (`ask`), the cards it expects in order (`cards`: the tool, its level, words its title must have, its payload, `untrusted`, and `decide`: `approve`, `decline` or `{decline: "the note"}`, with `before` for something the member does while the card waits), the world laid down first (`world`, under `Harness` only; `null` keeps the last one) and the checks after (`checks`: `file`, `noFile`, `trashed`, `notTrashed`, `page`, `noPage`, `reply`, `cards`, `cardState`, `cardUntrusted`, `noCard`, `chip`, `session`, `summary`, `untrusted`, `audit`). `kind: "member"` is something the member does with no ask (the Notebook's Undo), `kind: "shots"` only takes pictures, `skip` says why a step can't run on a desk, `needs: ["fixture"]` waits for `MA_AGENT_FIXTURE_BASE`, `freshAgent` starts a clean thread, and `unexpected: "decline"` notes a card the case didn't expect instead of failing. `{stamp}`, `{token}`, `{token2}`, `{fixture}` and `{form}` are filled in per run.

Then `node tests/real-desk/rt-agent-tools.mjs --tool <name> --dry` validates it and prints its plan, and `node --test 'tests/real-desk/agent-tools/*.test.mjs'` keeps the cases, the driver's card reading, the page's guards and the RTT shim honest (no browser). The stubs in `index.mjs` say what auto-approve, To-dos, Courier read and desk messages will check when they land. `agent-tools/NIGHTLY.md` proposes running both scripts nightly through the regression controller.
