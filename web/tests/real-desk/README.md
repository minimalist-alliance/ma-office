# Real-desk checks

Scripted Playwright runs against the real test desk on staging (`DeskKind=test`), run before a Desk app release goes to prod. They sign in as `desk-1` with credentials read from SSM, which are redacted from every log and never printed. They refuse to focus or wake anything but `<test-desk>`, and they fail if anything sends `start: true` unexpectedly. `rt-signin.mjs` is the exception, with its own account and no desk. Never point them at another account or at prod.

**A connected desk's label** is `online · …` until its `desk-agent` answers `agent.state`, and then that word (`no key`, `agent online`, and so on). `waitPanel(/online/)` takes any of them as connected, and `rt-lib.mjs` exports that set as `CONNECTED` (`rt-stage1.mjs` step 2 uses it).

**The layout follows the member** (`shell/layoutSync.ts`): with a bundle that has it, every script but `rt-stage2.mjs` reads its account's real document at load and saves what it changes there, so a run on `desk-1` starts from where the last one left the desks, not from a fresh browser's defaults.

Run from `web/` with Node 24 and AWS read access to `/ma/staging/test-users/desk-1`. Output and screenshots go to `test-results/real-desk/`. **Look at a screenshot**: passing checks have missed visual breaks.

```bash
MA_EXPECT_VERSION=2026.11.05-abc1234 node tests/real-desk/rt-stage1.mjs
```

| Script | What it checks |
|---|---|
| `rt-stage1.mjs` | Focus, Account panel, click outside, desk drag |
| `rt-stage2.mjs` | Layout migration, desk growth. Its pointer check predates edge panning, so 16 units of pan under a still pointer is expected. The layout sync's calls go to an in-memory stand-in for Platform's document that starts never saved, so the seeded layout is the one that loads and `desk-1`'s real document is neither read nor written; step 5 checks the sync read and that nothing passed the stand-in |
| `rt-stage3.mjs` | Moving and resizing apps. **Its overlap and contact checks describe the no-overlap rule, which ADR 0064 reversed: update them when stacking ships** |
| `rt-stage4.mjs` | Cleanup and undo. Step 2 fails on the known glide overlap, which ADR 0062 accepts |
| `rt-wake.mjs --wake` | The desk is stopped: wake from the app and time it. Without `--wake` it stops the desk first |
| `rt-watch.mjs --minutes N --log F --expect-version V` | Holds a tab and logs every link event. An open tab keeps a desk from idling, and `member-1` isn't involved |
| `rt-stack.mjs` | Stacking: an app dropped over another stays, on top, through a reload; Cleanup leaves no overlap and undoes. The desk must be running |
| `rt-desks.mjs` | Desks never overlap: dragging the test desk into its neighbour pushes it, through a reload. The other desk only moves on the canvas |
| `rt-hidden.mjs` | The hidden count: an app wholly covered shows the count, its list brings it to the front, Cleanup clears it. The desk must be running |
| `rt-browser.mjs` | The real Browser window, in full Chromium: picture, tabs, navigation, a click, closing, and CSP violations with real video. The desk must be running |
| `rt-sound-hidden.mjs` | Sound in a hidden tab (ADR 0038). Without `MA_EXPECT_VERSION` it routes this checkout's `dist/release` in place of staging's bundle, so run `npm run build:release` first; with it, staging's own bundle, which must be that version. `SOUND_PARTS=2` runs only the fast-clock part (about 5 minutes). Music on a still page from a page server of its own on the desk (port 18769, removed at the end): past 5 real minutes hidden it's still `live` and the sound still comes; a minute after the music ends it's `warm`; showing the tab brings the picture back. Then past 60 fake minutes on the page's clock, the session stays open while it plays and closes once it's quiet, and reopens with `start: false`. It logs the tabs it found, and fails if the desk still sends sound once it has closed its own tab. Hold `~/work/.test-desk.lock`; about 20 minutes. "Hidden" is `document.hidden`, since headless Chromium never hides a page. Results in `test-results/real-desk/rt-sound-hidden/report.json` |
| `rt-agent.mjs` | The Agent window on the real relay. Without `MA_EXPECT_VERSION` it routes this checkout's `dist/release` in place of staging's bundle, so run `npm run build:release` first; with it, staging's own bundle, which must be that version. The desk must be running, and nothing wakes it. Providers and agents list, the topics are asked for, a made-up key (Anthropic's prefix, 24 random hex characters) is refused with the right words and appears in no console line, storage, cookie, URL or field, nor in the desk's journal (over SSM, a count only), limits and activity load, no CSP violations or console errors, and the restart line shows or not by what the desk really returned: none where a key carries `available` or `agent.limits.get` has `timeZone`, the signs of the key store (`keysLast`). Limits (ADR 0043), in a browser on America/Denver: where nothing sets a zone, the window sets that one, alone, once, and today resets at midnight there; the whole desk's day set to $3.17 sends only `deskDay` of the desk's values, and "Use my account’s" (or "Remove the limit") sends `null`, leaving the desk following its account as before. So the one change it leaves on a desk with no zone is that zone, as any member's first visit would. What it reads off the `rpc` channel is names and shapes, never a value or a param, but for which limit fields `agent.limits.set` carried and whether each was null. It can't prove a real model reply: no test has a provider key. Hold `~/work/.test-desk.lock`; about 2 minutes. Screenshots and `result.json` go to `test-results/real-desk/rt-agent/` |
| `rt-notebook.mjs` | The Notebook on the real desk, with this checkout's `dist/release` routed in place of staging's bundle (or staging's own, with `MA_EXPECT_VERSION`), in full Chromium. Hold the lock, at most 45 minutes: `flock ~/work/.test-desk.lock timeout 45m nice -n 15 node tests/real-desk/rt-notebook.mjs`. The desk must be running, or `--wake`. While `notebook.tree` answers `not_found`: the calm line, nothing to type into, one question, nothing on `collab`, no console errors and no CSP report. Once it answers (17 steps, about 70 s): a new page takes focus by itself within 3 s and its Title takes typing, confirmed; still there after a reload on a new session; a line added at the end lands at the end; a second tab on the same page, each tab's line reaching the other, at the end and in order; a version saved and shown in History; search finds it; a paste of about 1.6 MB goes in several messages, none near 1 MiB, saved and whole after another reload with no leaving prompt; both pages to Trash by id; no CSP report and no console error. `test-results/real-desk/rt-notebook/report.json` has every step, and the next Playwright run wipes it, so copy it out |
| `rt-one-live.mjs` | One live picture per member (task 46, lever 2), with this checkout's `dist/release` routed in place of staging's (or staging's own, with `MA_EXPECT_VERSION`), in full Chromium. Hold the lock: `flock ~/work/.test-desk.lock timeout 45m nice -n 15 node tests/real-desk/rt-one-live.mjs`, about 3 minutes. The desk must be running; nothing wakes it. The desk looked at hears `desk.attention.set {seen: true}`; the overview and a hidden tab send `{seen: false}`, and the window keeps a still with no stream on its element; the switch back is timed `SWITCH_RUNS` times (5) after `AWAY_MS` (8 s) away, from the click to the signal leaving, to `deskd`'s answer and to the first real frame, with every display frame in between looked at for a blank one. On a `deskd` that knows the method, `FROZEN_RUNS` (2) more wait in the overview until the topic says `frozen: true` (60 s with nobody viewing the Browser, up to `FROZEN_WAIT_MS`, 120 s) and time the switch back from a truly frozen desk: the answer's `frozen`, the topic's thaw, the first frame, whether "Resuming…" showed, and that the stream is asked nothing (about 5 more minutes). It logs what `deskd` answers to the method and the topic (`not_found` before the Desk Engineer's part) and reads only names, `seen`, `state`, codes and versions off `rpc`. Results and screenshots in `test-results/real-desk/rt-one-live/`, which the next Playwright run wipes, so copy them out |
| `rt-simple.mjs` | The Browser's simplified view (task 47) on the real desk, with this checkout's `dist/release` routed in place of staging's (or staging's own, with `MA_EXPECT_VERSION`), in full Chromium. Hold the lock: `flock ~/work/.test-desk.lock timeout 45m nice -n 15 node tests/real-desk/rt-simple.mjs`, about 5 minutes. The desk must be running; nothing wakes it. It asks whether the desk serves section 14 (and stops there if not), then types a few public, document-like pages into the address bar (`SITES`, comma-separated; the default is a Wikipedia article, a Stack Overflow question, the first story on NPR's text-only front page and a DuckDuckGo HTML search): whether the view showed and how long after Enter, how long after the window opened again on it with the stream's first frame timed beside it, and whether the hidden control's "Show the real page" (this page only, never remembered) brings a playing picture back; then a missing Wikipedia article (`http_error`), which must stay the real page with its picture playing. Nothing is signed in or typed into a page, the switch is never pressed (so the desk's site memory is untouched), and the tab goes back to its address at the end. It reads only method names, codes, `view`, fallback reasons and versions off `rpc`. Window shots and `report.json` go to `test-results/real-desk/rt-simple/`, which the next Playwright run wipes, so copy them out; the shots show real sites, so they stay out of git |
| `rt-csp-windows.mjs` | Opens every app window on a running test desk and counts CSP violations and console problems. Never wakes the desk |
| `rt-ice.mjs` | ICE restart. Read it before running: it blocks traffic |
| `prod-load.mjs` | Loads prod signed out and prints the bundle version. No account. It ends on managed login at `auth.`, so its `url` and `text` are that page's |
| `rt-managed.mjs --expect-version V` | What prod does, on staging, whose `auth.signInPath` is on: it takes that field out of client-config in this browser only, and changes nothing anywhere else. Signed out and a really refused token go straight to real managed login with no card, the guard ends a second round at the card, a bare `/auth/callback` and `/signed-out` keep it. No account, no sign-in and no desk: the token it refuses is made up. Screenshots go to `test-results/real-desk/managed/` |
| `rt-signin.mjs --expect-version V [--user direct-1]` | Sign-in on `office.staging`, no desk needed, so not `desk-1`: `/account` goes to `platform.`, signed out goes to the form with no card, the menu's Account link, a really revoked session lands on the form with the line and returns to its path, a bad or bare `/auth/callback` lands on the form with the error, a sign-out keeps its card, and prod's version. It takes `direct-1` or `e2e-signup` only, never one that starts an EC2, signs in at most twice, each at the start of a fresh TOTP window, stops on a refused code with no retry, and proves with real Cognito that a sign-out's token is revoked. It prints `POST /v1/me/sign-out`'s blocked call as a NOTE: that route isn't on the API yet, so its 404 has no CORS headers, and the app carries on to revoke. Any other console error fails it. Screenshots go to `test-results/real-desk/signin/` |
